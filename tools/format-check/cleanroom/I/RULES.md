# Rules of validity of a seqlz compressed block

Taken from `format.md` only. Sentences marked *Why:* were not used as rules. Names are as in format.md:
`len`, `h`, `n`, `t`, `code`, `w`, `e`, `dt`, `s[j]`, `d`, `B`, `used`, `out`, `last`, `BLOCK = 4096`.

**The base block.** Where a change can be shown on concrete bytes, it starts from the example of
format.md, `02 00 61 62 23 f2 ff fb 60` (raw literals `a b`, one escaped token 1010 = ll 2, mlf 31,
class 1, offset bit 1, ML symbol 23 `1111111`, `read(11)` = 2011, 5 zero bits of padding). Bits of `B`
are numbered from 0 as in format.md, so byte `23` holds bits 0–7, `f2` bits 8–15, `ff` bits 16–23,
`fb` bits 24–31 and `60` bits 32–39. Rules about coded literals or a block's own table cannot be shown on
the example, so their change is described on "a valid coded block" with the needed property.

"Breaks no other" means no other rule in the list fails. Where no change can break a rule alone, the row
says so and names the rules that break with it.

## 1. Rules stated in format.md

| ID | Section | Sentence quoted | Condition on the bytes (block invalid if …) | Smallest change of a valid block that breaks only this rule |
| --- | --- | --- | --- | --- |
| R1 | Layout of a compressed block | "A block is invalid if – `len < 2`, or `n > BLOCK`;" | `len < 2`, i.e. there is no byte 0 or no byte 1. | Cut the example to its first byte: `02` (`len = 1`). No other rule can be checked without `h`. |
| R2 | Layout of a compressed block | "15 bits could count up to 32767, but a block has at most `BLOCK` literals, and `n > BLOCK` is invalid in both layouts." / "`len < 2`, or `n > BLOCK`" | `(byte0 + 256*byte1) & 0x7fff > 4096`. | **Cannot be broken alone.** Smallest change: byte 1 of the example `00` → `10`, which makes `n = 4098`. That also breaks R3, because `2 + n > len`. If the 4096 missing literal bytes were added to satisfy R3, decoding would still fail, since `n - BLOCK > 0` never reaches 0 (see I2). So R2 also follows from the Decoding rules (I1/I2). It only makes the decoder reject the block early. |
| R3 | Layout | "with raw literals `2 + n > len`;" | `h & 0x8000 = 0` and `2 + n > len`. | Cut the example to `02 00 61` (`len = 3 < 4`). R1 and R2 still hold. `B` is not reached. |
| R4 | Layout | "with coded literals `len < 3`, which leaves no byte 2," | `h & 0x8000 ≠ 0` and `len < 3`. | Cut any valid coded block to its first 2 bytes. |
| R5 | Layout | "… or `len < 3 + w + e`," | coded, `len ≥ 3`, `len < 3 + w + e` with `w = 5 + ((t>>4)&7)`, `e = t>>7`: the `dt` byte or the stream sizes are cut off. | Cut a valid coded block to `3 + w + e - 1` bytes. **Note:** for validity this rule is implied by R9, because `3+w+e > len` gives `3+w+e+d+Σs > len`. It cannot be broken without R9 also failing. It says the sizes must be present before they are used. |
| R6 | Layout | "`dt` is not 1, 2 or 3," | coded, `e = 1` (bit 7 of byte 2), and byte 3 ∉ {1, 2, 3}. | In a valid coded block with `e = 1`, change byte 3 to `00` (or `04`). Because every value of `dt` is rejected before any literal is restored, nothing else is checked. |
| R7 | Layout | "`code > 8`," and "`code` 8 is a table of the block's own, and 9 to 15 are invalid." | coded and `(byte2 & 15) ≥ 9`. | In a valid coded block with `code = 8`, add 1 to byte 2 (code 9). With a fixed table (`code` 0–7), set the low nibble to 9 to 15. Either way R7 fails first. |
| R8 | Layout | "the block's own table is invalid," | coded, `code = 8`, and one of R8a–R8e. | See R8a–R8e. |
| R8a | A block's own literal table | "The block is invalid if the sum goes above 1," | While the `OWN` symbols are read, `Σ 2^-l` over the lengths so far becomes > 1. The list stops at the first sum that is ≥ 1. | In a valid own table whose last code has `l >= 2` (always true, since a complete table has 2 or more codes), replace the last length symbol `l-1` with `l-2` (one bit shorter). The sum jumps from below 1 to above 1 there. The `OWN` code of the new symbol may differ in length, but the table ends at that symbol in either case. Any padding after it must be kept 0 (R8d), and `d` must not grow past `len` (R8e). |
| R8b | A block's own literal table | "a byte value with a code is above 255," | A length symbol (`OWN` 0–9) is read when the next byte value is 256. | In a valid own table with a run before the codes at the top, raise that run's `r` by 1 (same `k`, same number of bits; if `r` is already `2^(k-1) - 1`, use `k + 1`, `r = 0`) so that the last coded byte value moves from 255 to 256. The run itself does not pass 255. |
| R8c | A block's own literal table | "a run of byte values without a code goes past 255" / "A run past 255 makes the block invalid at once, the list does not go on after it." | A run symbol (`OWN` 10–18) with `k`, `r` is read at next byte value `v`, and `v + 2^(k-1) + r > 256`. | In a valid own table, raise the `r` of a run (or its `k`, if needed) so that the run ends past 255. Every later symbol is then not read. |
| R8d | A block's own literal table | "a bit after the last symbol in its byte is not 0," | In the byte that holds the table's last bit, a later bit (lower in value) is 1. | In a valid own table whose bit count is not a multiple of 8, set the lowest bit of its last byte. Neither `d` nor the streams move. |
| R8e | A block's own literal table | "or `3 + w + e + d > len`" / "Bits past `len` are read as 0, and `3 + w + e + d > len` then makes the block invalid." | The own table, read with zeros past `len`, ends after byte `len - 1`. | **Cannot be broken alone.** It implies R9 for validity, because `Σs ≥ 0`. Smallest change: cut a valid `code = 8` block inside its table. |
| R9 | Layout | "or `3 + w + e + d + s[0] + ... + s[7] > len`." | coded, and the header plus the own table plus the 8 streams do not fit in `len`. | Take a valid coded block with `n = BLOCK`, which has an empty `B` (see I4), and cut its last byte. The last non-empty stream is then cut. Its bits, as counted, still fit its `s[j]`, so R13–R15 still hold. |
| R10 | Prefix codes / A block's own literal table | "Every table is **complete**: … `2^-l` summed over all codes is exactly 1." / "The list ends as soon as the codes fill the code space" | For the own table, this is not a separate check: a table whose sum never reaches 1 fails R8b, R8c or R8e (see I12). For the fixed tables it is a claim about the tables, CLAIMS C20. | — (not a separate condition) |
| R11 | The bitstream of the sequences | "A block that needs a bit past the end of `B` is invalid." / Decoding: "no bit read past the end of B" | Decoding uses bit `i ≥ 8·|B|`. | Remove the last byte of the example: `02 00 61 62 23 f2 ff fb`. `read(11)` needs bits 32–34. |
| R12 | The bitstream of the sequences | "after the last bit it needs, fewer than 8 bits of `B` are left, all in its last byte," | `8·|B| - (bits used) ≥ 8`, i.e. there is a whole byte after the byte with the last used bit (or `B` is not empty although no bit is used). | Append `00` to the example: `… fb 60 00`. |
| R12b | The bitstream of the sequences | "… and they are 0." / Decoding: "fewer than 8 bits of B left, all 0" | One of the at most 7 bits after the last used bit is 1. | Example last byte `60` → `61` (bit 39 set). Bits 35–39 are padding. |
| R13 | Tokens | "`if token >= 3072: the block is invalid`" | An escape (`TOK` symbol 3072) is followed by `read(12) ≥ 3072`. | Example byte `23` → `2f`. The 12 escape bits become `1111 1111 0010` = 4082. |
| R14 | Offsets / Decoding | "an offset of 0, which classes 1 to 5 give for offset bits of 0, … makes the block invalid" / "`if off == 0 … invalid`" | A class 1–5 token whose offset bits are all 0. | Example byte `ff` → `7f`: the class-1 bit becomes 0, so `off = 0`. `ml` is still 4094. |
| R15 | Offsets / Decoding | "or one larger than `|out|` after this sequence's literals are copied" / "`off > |out|`" | `off > |out|` after `copy(ll)`. | Example byte `f2` → `f1`: token 1009, `ll = 1`, `off = 2 > |out| = 1`. `ml = 4094 ≤ 4095`, so the `ml` check holds. |
| R16 | Decoding | "`ml > BLOCK - |out|`: invalid" | The match would write past byte 4095. | Example byte `60` → `80`: `read(11)` = 2012, so `ml = 4095 > 4094`. Bits 35–39 stay 0. |
| R17 | Decoding | "`if ll > n - used … invalid`" | A sequence's literal length is more than the literals left. | Example byte `f2` → `f3`: token 1011, `ll = 3 > 2`. |
| R18 | Decoding | "`… or ll > BLOCK - |out|: invalid`" | `ll` is more than the bytes left in the block. | **Cannot be broken alone.** If `ll ≤ n - used` but `ll > BLOCK - |out|`, R16 also fails, because `ml ≥ 4 > BLOCK - |out| - ll` (given the ML bits are there). This state is reached only when `n - used > BLOCK - |out|`, which in turn happens only after a match left too few bytes (see I2). Smallest change: on the example, make `n = 3` (insert a third literal, `03 00 61 62 63 …`) and append, after the 35 used bits, a token with `ll = 1` and its offset bits. R18 fires before ML is read. In the order of checks it is the first rule broken, but validity alone would also be decided by R16. |
| R19 | Coded literals | "has literals whose codes take `bits` bits, and not `8 * s[j] - 8 < bits <= 8 * s[j]`: the codes end in the stream's last byte;" | For each stream `j < min(n, 8)`: `s[j] ≠ ceil(bits_j / 8)`. | In a valid coded block, add 1 to `s[j]` of one stream with literals. If `s[j]` is at its largest for `w`, raise `w` instead. Insert one `00` byte at the end of that stream. The streams after it and `B` move by one byte, as `start[]` says. |
| R20 | Coded literals | "has literals, and a bit after the last code in the stream's last byte is not 0;" | A padding bit after the last code of stream `j` is 1. | In a valid coded block with a stream whose `bits_j` is not a multiple of 8, set the lowest bit of that stream's last byte. |
| R21 | Coded literals | "has no literals, which are streams `n` to 7 when `n < 8`, and `s[j]` is not 0." | `n < 8` and `s[j] ≠ 0` for some `j ≥ n`. | In a valid coded block with `n < 8`, set `s[7] = 1` and insert one byte (any value) at `start[7]`. **Note:** a valid block with `n < 8` and coded literals exists only for `1 ≤ n ≤ 7` (I1), e.g. 1 literal and a match of 4095. |

## 2. Implied rules (not written anywhere as one rule)

| ID | Rule | Follows from |
| --- | --- | --- |
| I1 | **`n` is `BLOCK` or 1 ≤ `n` ≤ `BLOCK - 4`.** `n = 0` and `n` = 4093, 4094 or 4095 are always invalid, in both layouts. | Decoding: "`if n - used == BLOCK - |out|`: the last sequence" and "Every match is at least 4 bytes" (`ml = mlf + 4`, `mlf ≥ 0`). Also "a valid block has `n >= 1`, because the first match needs a byte before it" (stated in format.md, with only the lower bound). With `D = (n - used) - (BLOCK - |out|)`, each sequence adds `ml ≥ 4` to `D`, and the block stops only at `D = 0`. `D` starts at `n - BLOCK`, so for `-4 < n - BLOCK < 0` it jumps past 0. |
| I2 | **The matches fill exactly `BLOCK - n` bytes, and every literal is used.** Once `n - used > BLOCK - |out|` (a match left fewer bytes than literals), the block is invalid. | The stop condition in Decoding, "`ll > n - used or ll > BLOCK - |out|`", "`ml > BLOCK - |out|`", and that the block needs a token while `D ≠ 0`. |
| I3 | **`len` is fixed by the content: no byte may follow the last byte that is used.** With raw literals `len = 2 + n + ceil(bits_B / 8)`. With coded literals `len = 3 + w + e + d + Σ s[j] + ceil(bits_B / 8)`, with `s[j] = ceil(bits_j / 8)` and `d = ceil(bits_own / 8)`. | R12 (fewer than 8 bits left), R19 (`s[j]` is exact), "`d` is its number of bytes", the layout tables. The only free choices in the header are `w` (as long as every `s[j] < 2^w`), `code`, `e` and `dt`. |
| I4 | **`n = BLOCK` ⇔ `B` is empty**, and with `n < BLOCK`, `B` holds at least one token. | Stop condition (true at once with `n = BLOCK`), R12 (no bit used ⇒ no byte of `B`), I2. format.md says it ("a block of literals only has `n = BLOCK` and no bits in `B`"), but not as a condition on `|B|`. |
| I5 | **A class-1 offset bit must be 1.** Class 1 can only send offset 2. | Offsets table "`read(1) * 2`", R14. |
| I6 | **The first sequence has `ll ≥ off ≥ 1`.** So it has `ll ≥ 1`. With class 0 it has `off = 1` (copies the last literal). With class 2 or 3, the offset bits must not exceed `ll`. With class 4 or 5, `ll ≥ 8`. | R14, R15, "The last offset starts as 1 for each block", `|out| = ll` after the first `copy`. format.md states "the first match's offset is at most that sequence's `ll`". The class-by-class consequences are not written. |
| I7 | **Every stream with literals has `1 ≤ s[j] ≤ 640`.** | R19, every code is 1 to 10 bits (fixed tables: longest code 10; own table: `l` 1 to 10), and a stream holds at most 512 literals. format.md gives 640 only as a *Why:*, not as a bound on `s[j]`. A larger `s[j]` breaks R19. |
| I8 | **No `s[j]` can say a stream size of `2^w` bytes or more.** A block whose largest stream needs `s[j] >= 2^w` has no valid encoding with that `w`, because any other `s[j]` breaks R19. It needs a larger `w`. Since `s[j] <= 640` (I7), `w = 10` is always enough; 11 and 12 are never needed, but they are valid (V5). | Layout (`s[j]` is `w` bits), R19, I7. |
| I9 | **The order of the fields of a sequence in `B`**: TOK symbol, [12 escape bits], offset bits of the class, [LL value: symbol + `read(b)`], [ML value: symbol + `read(b)`]. The offset bits come before the LL value. | Decoding pseudocode (`x = read(...)` before `if ll == 15`), Length values, Tokens. The example confirms the offset bit comes before the ML value, but it has no LL value. |
| I10 | **A value of `LL` or `ML` that is coded but too large is invalid**: `15 + value(LL) > min(n - used, BLOCK - |out|)` or `35 + value(ML) > BLOCK - |out|` after the literals. The symbols 23 (`b = 11`) of `LL` and `ML` are valid only with a value that fits. | Length values (values up to 4095, `ll` up to 4110, `ml` up to 4130), R16, R17. |
| I11 | **A valid block has at most 1023 tokens (1024 sequences).** | `n ≥ 1` (I1) and `ml ≥ 4` for each token give `4·tokens ≤ BLOCK - 1`. format.md's bound `BLOCK / 4 + 1` = 1025 counts also blocks that are not valid. |
| I12 | **A valid own table ends with a length symbol, has at least 2 byte values with a code, never contains symbol 18, and no run in it may reach byte value 255.** A run that ends exactly at 255 does not "go past 255" (R8c), but the table cannot be complete (no code was added, so the sum is still < 1), and the next symbol is either a code above 255 (R8b) or a run past 255 (R8c). If the bits run out, zeros are read, and then R8e/R9 apply. | "The list ends as soon as the codes fill the code space", R8b, R8c, R8e. format.md states the symbol-18 part. |
| I13 | **The own table can make no literal undecodable, but a literal stream can only contain byte values that have a code.** There is no rule for "a literal with no code". This is because the codes are complete (R8a / the end rule), so every bit string decodes. | Prefix codes ("a decoder never meets bits that are no code"), A block's own literal table. |
| I14 | **Fixed tables: no bit string in `B` or a stream is "not a code".** The only invalid cases in `B` are R11–R18. | All fixed tables are complete (C20). In particular, `TOK` symbol 3072 followed by 12 bits is the only way to send a token without a code. |
| I15 | **With raw literals `e`/`dt` do not exist**, so a raw block can never have deltas. With coded literals, `dt` is checked only when `e = 1`. | Layout tables (raw layout has no byte 2), "with `e = 1` the byte `dt`". This is one reading; see QUESTIONS Q1. |
| I16 | **The literal streams are valid or invalid independently of `B` and of `dt`.** Deltas change the restored bytes, not the stored symbols, and no rule restricts restored bytes. | Coded literals rules (only bit counts and padding), Literals as deltas (only arithmetic mod 256). |
| I17 | **`len ≥ 2 + n`, so with raw literals and `n ≥ 1`, `len ≥ 3`.** The smallest valid block is raw, with `n = 1` and `B` holding one token (`ll = 1`, `off = 1`, `ml = 4095`). An empty `B` is valid only with `n = 4096`. | I1, I4, R3. |

## 3. Valid, although one might expect it not to be

| ID | Case | Why valid (sentence) |
| --- | --- | --- |
| V1 | A token sent escaped although it has a code of its own. | Tokens: "Any token can be sent escaped, also one that has a code of its own; it means the same." |
| V2 | An offset sent with a class that is not the cheapest (e.g. offset 2 with class 2 or 3, offset 8 with class 3, 5 or 4), or not with class 0 although it equals `last`, or with class 0 when the class with offset bits would be shorter. | Offsets table; "What the compressor writes" is "Not part of the format: any block that decodes is fine". |
| V3 | Class 0 in the first sequence of a block: offset 1, although there is no "sequence before". | "The last offset starts as 1 for each block." |
| V4 | A match with `off < ml` (it overlaps itself), e.g. `off = 1`. | Decoding: "it can repeat bytes it writes itself". |
| V5 | A `w` larger than needed, up to 12, although no stream can be over 640 bytes (10 bits): `w` 11 and 12 are never needed. | Layout: "`w` is 5 to 12"; no rule asks for the smallest `w`. Only the compressor picks it ("the smallest `w` that holds every `s[j]`"). |
| V6 | Coded literals that take more bytes than raw ones. A fixed table that is not the best. `code = 8` for fewer than 512 literals, or an own table that is larger than a fixed one would be. Deltas (`e = 1`) that do not pay. | Only the compressor section has these limits ("`m + d + Σs < n - n div 16`", "512 literals or more", "32 bytes less"), and it is "Not part of the format". |
| V7 | `e = 1` where no literal has `p ≥ x`, so every literal is stored as it is (e.g. `dt = 3` after a large offset, or all literals in the first 3 bytes). | Literals as deltas: "if `p < x`, there is no such byte, and the literal is stored as it is." |
| V8 | A delta against a byte written by a match, by this same `copy`, or in the last sequence. | "`out[p - x]` is any byte already written, of a match or a literal, of this sequence or an earlier one … The last sequence is no different." |
| V9 | `dt = 3` and the first sequence (or a block without matches): `x = 4`, the same as `dt = 1`. | "`last` … 1 for the first: `x = 4` for `last` 1 or 2". |
| V10 | A block that ends with a match (last sequence has 0 literals). | Decoding: "A block whose last match reaches the end of the block ends with no literals left". |
| V11 | Sequences with `ll = 0`, except the first (I6). `ll = 15` sent as token field 15 with `value(LL) = 0`, and `ml = 35` as `mlf = 31` with `value(ML) = 0`. | Tokens, Length values (value 0 is symbol 0). |
| V12 | `B` whose last byte is `00`, i.e. the last used bits are 0. Also up to 7 zero bits of padding, which may even look like the start of a `TOK` code. | Bitstream: only "fewer than 8 bits … and they are 0". The test list in "How this file was checked" speaks of "a token after the last sequence whose bits are not 0, which is invalid", so a zero padding is no token. |
| V13 | A block of literals only (`n = 4096`) with **coded** literals, and with an empty `B`. Also `e = 1` with `n = 4096`. | Layout; I4. |
| V14 | Coded literals with `n < 8` (empty streams, `s[j] = 0`), even `n = 1`. | Coded literals: "has no literals, which are streams `n` to 7 when `n < 8`, and `s[j]` is not 0" (only `s[j] ≠ 0` is invalid). |
| V15 | An offset equal to `|out|`, which copies from byte 0. A match that ends exactly at byte 4095. | Only `off > |out|` and `ml > BLOCK - |out|` are invalid. |
| V16 | An own table that gives codes to byte values no literal has, or two run symbols in a row, or a run of length `2^(k-1) + r` written with a larger `k` than needed, or `k = 1` runs repeated. | A block's own literal table: no rule forbids them. Only the sum, the range of byte values and the padding are checked. |
| V17 | An own table whose `OWN` symbols say lengths up to 10 bits, although `OWN` itself has codes of at most 8 bits. | "symbol `l - 1`, for `l` from 1 to 10". |
| V18 | Fixed literal tables: any byte value can be coded with any of the 8 tables, because each of the 8 has a code for all 256 byte values (checked on `tables/LIT.bin`, no length 0). | The tables. |
| V19 | Bits of `B` that the decoder reads ahead, past the end or into nothing, as long as they are not used. Streams that a decoder reads past into the next stream. | Bitstream: "A decoder may read zeros past the end … and check at the end that it did not use them". Coded literals: "A decoder may read past the end of a stream … if it checks these rules". |
