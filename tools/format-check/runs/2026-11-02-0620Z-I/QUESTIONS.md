# Places in format.md that can be read two ways

| ID | section | sentence quoted | readings |
| --- | --- | --- | --- |
| Q1 | Offsets | "For a sequence with a match, an offset of 0, or one larger than the bytes written so far, makes the block invalid." | (a) "so far" is after this sequence's literals, as the pseudocode checks `off > \|out\|` after `copy(ll)`. (b) It is before them, at the start of the sequence. Under (b), E (off 2 after 0 bytes) would be invalid. The pseudocode and "the first match's offset is at most that sequence's `ll`" support (a). |
| Q2 | Own table | "a run of byte values without a code goes past 255" | (a) The run ends above 255 (`start + run - 1 > 255`). (b) It reaches 255 or beyond, i.e. it leaves no byte values. Both make the block invalid, because after a run that ends at 255 the next symbol is past 255 too. But they differ in which rule fails and where "at once" stops reading, which matters for `d` and for single-rule tests. |
| Q3 | Coded literals | "If stream `j` has literals, their codes take `b` bits with … A stream without literals … has `s[j] = 0`. Else the block is invalid." | (a) "Else" covers both sentences: a stream with literals that breaks the bit bound, or an empty stream with `s[j] != 0`. (b) It covers only the empty-stream sentence, and the first sentence is a description of what the compressor writes. "they end in the stream's last byte, and the bits after the last code … are 0" reads as a requirement, so (a). |
| Q4 | Bitstream / Decoding | "after the last bit it needs, fewer than 8 bits of `B` are left" / "at the stop: fewer than 8 bits of B left, all 0, else invalid" | (a) The block is also invalid if it needed bits past the end, since a negative number "left" is no bits left. (b) Read literally, "fewer than 8 left" includes a negative number of bits, so a cut block that uses zeros past the end would pass. The sentence "check at the end that it did not use them" supports (a). |
| Q5 | Decoding | "a decoder stops after at most `BLOCK / 4 + 1` sequences, also on blocks that are not valid" | (a) It counts loop rounds, including the one that fails. (b) It counts sequences decoded in full. Under (b) the bound is `BLOCK / 4` plus the last sequence, and on an invalid block one more token is read. |
| Q6 | How checked | "a last sequence with a token, which is invalid" | (a) A format rule: any token after the stop condition makes the block invalid. (b) A consequence of the end rule: it is invalid only because its bits leave 8 or more bits or non-zero bits. A token of up to 7 zero bits (`TOK` symbol 49 = `0000`) is then padding, and the block is valid (V9). |
| Q7 | Layout | "`3 + e` \| `w` \| `s[0]` to `s[7]` …, `w` bits each" with "`w` the bits of each stream size" | The size column is in bytes ("Sizes are in bytes unless they say bits"), so the field is `w` bytes. But `w` is defined as a bit count, and the column can be read as `w` bits. "8 sizes of `w` bits fill exactly `w` bytes" settles it as bytes. |
| Q8 | Layout | "with coded literals `len < 3` …, or `len < 3 + w + e`, `dt` is not 1, 2 or 3, …" | (a) `dt` is checked only with `e = 1` (it only exists then). (b) Byte 3 is always checked, even when `e = 0` and it is the first size byte. The layout table supports (a). |
| Q9 | Intro (both copies) | "level 2 codes them with one of 8 fixed tables where that pays, level 3 also with a table of the block's own, and stores them as deltas to earlier bytes of the block first where that pays" | (a) Only level 3 stores deltas. (b) Levels 2 and 3 both do. "What the compressor writes" says level 3, so (a). (This is not about the format.) |
| Q10 | Deltas | "where `last` is the offset of the sequence before, 1 for the first" | (a) The value of `last` in Decoding: the offset of the last match, also through class 0 runs. (b) The offset sent by the sequence just before, whatever its class. These are the same, but "sequence before" for the last sequence of a block with no match (n = BLOCK) only becomes clear through "1 for the first". |
| Q11 | Deltas | "Take a literal that `copy()` writes to byte `p` of the block … If `p >= x`" | Indexing isn't stated. (a) 0-based (`out[p - x]` exists iff `p >= x`). (b) 1-based, where the condition would have to be `p > x`. `out[p - x]` and `p >= x` imply (a). |
| Q12 | Bitstream | "`B` is all bytes from its start up to `len`" | "up to `len`" exclusive (bytes `start .. len-1`) or inclusive. It has to be exclusive, since byte `len` doesn't exist. |
| Q13 | Coded literals | "A decoder may read past the end of a stream, as long as it checks this." | (a) "this" is the bound `8*s[j] - 8 < b <= 8*s[j]` plus the zero padding. (b) "this" is that the bits read past the end were not used. The two readings agree on validity. It is also not said what is read past a stream: the next stream's bytes, or zeros. |
| Q14 | Offsets | the column "offsets it can send" | (a) A description. (b) A rule, so that e.g. class 1 with bit 0, or class 3 with 4093–4095, is invalid because it is outside the column. Both give the same validity because of the `off == 0` and `off > \|out\|` rules, but the column for class 3 says "1 to `BLOCK - 1`", which a valid block can't fully use (I4). |
| Q15 | The tables | "codes of at most" 8 bits for `ML` | (a) A limit the generator keeps. (b) The longest code in the table. `ML.bin`'s longest is 7, so under (b) the table is wrong. |
| Q16 | Status / How checked | "This is the format of 22nd October 2026" / "Until 1st November 2026 this file also had blocks of 16 KiB" | (a) The 4 KiB format has been unchanged since 22 Oct, and 1 Nov only removed the 16 KiB part. (b) The format changed on 1 Nov, and the date in Status is out of date. |
| Q17 | Notation / names | `read(n)` vs `n` the number of literals; `t` the byte 2 vs `t` the token in "Reading a token"; `x` the offset bits (Decoding), the delta distance (Deltas) and the run bits (own table); `b` the range bits (Length values) vs the code bits of a stream (Coded literals) | Each name can be taken for the other in the same paragraph. E.g. `read(n)` in Bitstream is a parameter, not the literal count. |
| Q18 | Own table | "symbol `l - 1`, for `l` from 1 to 10: the next byte value has a code of `l` bits" with "Every table is complete" (Prefix codes) | (a) "Every table" includes a block's own table, so completeness is a validity rule, enforced by the end-of-list rule. (b) It is only about the fixed tables. The results are the same, because the list can only end at sum = 1. |
| Q19 | How checked | "on 22nd October both decoders got every delta byte, every cut and random damage" | "every delta byte": (a) every value of the `dt` byte, or (b) every literal stored as a delta, damaged in turn. |
| Q20 | Layout | "`n > BLOCK` is invalid in both layouts" and the R-list order | The order of the checks isn't given. It doesn't change validity, but for a block that breaks two rules, which error a decoder reports is open. |
